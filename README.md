# Triplex в Pixso с GigaCode CLI

Плагин ставит LightBox из подключённой библиотеки Triplex. GigaCode CLI предлагает поля, а плагин вставляет их экземпляры в выбранную область после подтверждения.

## Запуск на рабочем компьютере

Если в окне остаётся старая версия, откройте манифест, который фактически подключён в Pixso. Проверьте файлы по путям `main` и `ui` относительно этого манифеста. Если сборщик пишет в отдельную папку, проверяйте выходные файлы. В заголовке окна и под выбором размера должна быть версия 21.11.1. Если обновился только заголовок, Pixso получил новый JS, но загружает старый HTML.

1. Для локального запуска подключите `manifest.json` из этой папки. Он загружает корневые `main.js` и `ui.html`. Если используете отдельный dev-проект, замените оба файла по путям из его манифеста и перезапустите dev-сервер. Закройте и снова откройте плагин. Под выбором размера должна появиться надпись «Сборка UI 21.11.1».
2. Проверьте, что установленный CLI доступен в терминале. Плагин рассчитан на [GigaCode CLI](https://gitverse.ru/docs/ai/ai-assistant-gigacode/gigacode-cli/). Для проверки выполните `gigacode -p "Ответь словом OK" --output-format json`. Ожидается JSON с полем `result`. Авторизация выполняется в самом CLI.
3. Запустите `node gigachat-bridge.mjs`. Скопируйте код подключения из второго терминала в плагин. Это код локального моста, он меняется при перезапуске. Мост слушает только `127.0.0.1:43127`, а запрос передаётся в CLI через аргумент `-p`.
4. Поставьте LightBox и выделите внутренний фрейм с автолейаутом. Если выделен сам LightBox, плагин ищет единственный `BodyPage` среди первых двух уровней.
5. Опишите задачу и нажмите «Предложить компоненты». Плагин подбирает кандидатов из библиотеки установленного LightBox по именам и группам. Для набора вариантов он использует вариант по умолчанию.
6. Обсудите предложение в чате и нажмите «Подтвердить набор компонентов». Для каждого компонента согласуйте свойства и тексты. После последнего подтверждения нажмите «Добавить на фрейм». Ошибки и состояния на этом этапе не предлагаются.

[Storybook Triplex](https://triplex-design.ru/next/ru/Web) и [исходники Triplex Next](https://github.com/SberBusiness/triplex-next) описывают назначение и поведение компонентов. Плагин получает экземпляры и свойства через каталог Pixso. Подсказки для модели ограничены типовыми элементами формы.

Если CLI отвечает из терминала, а окно Pixso не подключается, проверьте разрешение редактора или браузера на доступ к локальной сети. Плагин отправляет описание задачи и имена и назначение предложенных компонентов. Учётные данные GigaCode остаются в CLI.

## Верстка, состояния и ошибки

1. После вставки компонентов расставьте их на фрейме и настройте размеры в Pixso.
2. Нажмите «Закрепить верстку». Исходный фрейм блокируется для редактирования. Для правок используйте «Изменить верстку», затем закрепите макет повторно.
3. Нажмите «Добавить состояния». Только теперь модель впервые предлагает ошибки, варианты и состояния на основе кейса и фактических компонентов на фрейме. Проверяются обязательность, формат, диапазон, зависимости, сеть, сервер и другие применимые случаи; неподтвержденные бизнес-правила помечаются как гипотезы.
4. Возле каждого состояния и каждой ошибки переключите «+ Берём / − Не берём». Дополните описание кейса в чате и запросите дополнительные предложения. Решения для совпадающих состояний и ошибок сохраняются.
5. Нажмите «Утвердить состояния и ошибки», затем «Создать выбранные состояния рядом с фреймом». Плагин копирует закрепленный экран рядом с исходным, сохраняет размеры фрейма и компонентов, применяет доступные варианты и свойства. Исключенные ошибки и соответствующие им варианты не добавляются.

Условия и сообщения ошибок также видны под каждой копией. Если библиотека не предоставляет текстовое свойство ошибки, сообщение остается в этой подписи для ручного оформления. Недоступный вариант останавливает создание и удаляет незавершенные копии. Изменение исходной верстки требует повторного закрепления и согласования состояний.

Кнопки исключены из каталога. При подборе компонентов модель должна обосновать выбор типов: дата, список, переключатель и многострочный текст не должны автоматически заменяться TextField. Удален прежний лимит первых четырех компонентов каждого семейства; точное имя компонента имеет приоритет над категорией каталога.

## Проверка

`node --test tests/workflow.test.cjs` — проверки каталога, этапов UI, закрепления макета, выбора ошибок, размеров копий и отката при ошибке. Используются заглушки Pixso; для интеграционной проверки необходимы Pixso, подключенная библиотека Triplex и авторизованный GigaCode CLI.
